21. Пищалка
Напишите программу, которая входит в бесконечный цикл и издает звуковой сигнал на вашем терминале каждый раз, когда вы вводите символ, на который у вас настроена посылка сигнала SIGINT (по умолчанию CTRL-C). При получении SIGQUIT, она должна вывести сообщение, говорящее, сколько раз прозвучал сигнал, и завершиться.

# 21: Пищалка (Сигналы SIGINT/SIGQUIT)

## 1. Подготовка рабочего места
Переходим в директорию задания и создаем новую папку:

cd ~/MyOSTest
mkdir task_21
cd task_21

## 2. Ключевые концепции для понимания задачи

• Асинхронные события: Сигналы прерывают нормальный ход выполнения программы в любой момент. Программа должна быть готова реагировать на них мгновенно.
• Безопасность в обработчиках: Внутри функции-обработчика сигнала можно использовать только функции (например, `write`, `_exit`). Использование `printf` или `malloc` может привести к взаимной блокировке (deadlock) или повреждению данных, так как они не являются реентерабельными.
• volatile sig_atomic_t: Специальный тип данных для глобальных переменных, которые изменяются в обработчиках сигналов. Ключевое слово `volatile` запрещает компилятору кэшировать значение в регистре, а `sig_atomic_t` гарантирует, что чтение или запись переменной выполнятся за одну неделимую (атомарную) операцию.
• pause(): Системный вызов, который приостанавливает выполнение процесса до получения любого сигнала. Это эффективнее пустого цикла `while(1)`, так как не нагружает процессор.

## 3. Шпаргалка: Сигналы в Unix

СИГНАЛЫ (signal.h)
• SIGINT: Сигнал прерывания (генерируется нажатием Ctrl+C). По умолчанию завершает процесс.
• SIGQUIT: Сигнал выхода (генерируется нажатием Ctrl+\). По умолчанию завершает процесс с созданием core-дампа.

ФУНКЦИИ И СТРУКТУРЫ
• int sigaction(int sig, const struct sigaction *act, struct sigaction *oldact):
  Надежный способ установки обработчика сигнала.
  - act->sa_handler: Указатель на функцию-обработчик (или SIG_DFL, SIG_IGN).
  - act->sa_mask: Маска сигналов, блокируемых во время выполнения обработчика (очищается через sigemptyset).
  - act->sa_flags: Флаги поведения. SA_RESTART заставляет прерванные системные вызовы (например, pause) автоматически перезапускаться после обработки сигнала.

• int pause(void): Приостанавливает выполнение процесса до доставки любого сигнала.

• ssize_t write(int fd, const void *buf, size_t count):
  Системный вызов записи, это безопасный способ вывести что-то на экран изнутри обработчика сигнала.

СПЕЦИАЛЬНЫЕ СИМВОЛЫ
• \a : Звуковой сигнал (bell/alert), ASCII код 7.
• \n : Перевод строки.

ВАЖНО
• Для завершения процесса из обработчика сигнала всегда используйте `_exit()`, а не `exit()`. Функция `exit()` пытается очистить буферы stdio, что небезопасно при асинхронном прерывании.
• Если при нажатии Ctrl+C на экране печатается `^C`, это режим терминала ECHOCTL. Его можно отключить через `tcsetattr`, убрав флаг `ECHOCTL` из `c_lflag`.

## 4. Основные библиотеки

#include <stdio.h>        // printf, snprintf
#include <stdlib.h>       // exit, EXIT_SUCCESS
#include <signal.h>       // sigaction, struct sigaction, SIGINT, SIGQUIT
#include <unistd.h>       // write, pause, STDOUT_FILENO, _exit
#include <string.h>       // strlen (опционально)

## 5. Алгоритм решения

1. Глобальная переменная:
   - Объявите `volatile sig_atomic_t beep_count = 0;` для безопасного подсчета сигналов.

2. Обработчик SIGINT (функция `sigint_handler`):
   - Вызовите `write(STDOUT_FILENO, "\a", 1)` для воспроизведения звукового сигнала.
   - Увеличьте значение `beep_count` на 1.

3. Обработчик SIGQUIT (функция `sigquit_handler`):
   - Создайте локальный символьный буфер (например, `char buffer[100]`).
   - Сформируйте строку с итоговым количеством сигналов, используя `snprintf`.
   - Выведите этот буфер и сообщение о завершении через `write`.
   - Завершите процесс вызовом `_exit(EXIT_SUCCESS)`.

4. Настройка обработчиков в `main`:
   - Объявите две структуры `struct sigaction` (например, `sa_int` и `sa_quit`).
   - Для SIGINT: установите `sa_handler`, очистите маску (`sigemptyset`), установите флаг `SA_RESTART`. Вызовите `sigaction`.
   - Для SIGQUIT: установите `sa_handler`, очистите маску, флаги можно оставить 0 (так как процесс все равно завершается). Вызовите `sigaction`.

5. Основной цикл:
   - Выведите приветственное сообщение через `printf`.
   - Запустите бесконечный цикл `while (1)`, внутри которого вызовите функцию `pause()`.

## 6. Сборка и тестирование

Создайте Makefile для сборки beeper.c:

CC = gcc
CFLAGS = -O2
TARGET = beeper
SRC = beeper.c

all: $(TARGET)

$(TARGET): $(SRC)
	$(CC) $(CFLAGS) -o $(TARGET) $(SRC)

clean:
	rm -f $(TARGET)

.PHONY: all clean

Команды для запуска:
make clean
make
./beeper

## 7. Пример проверки

**Шаг 1: Запуск**
./beeper
Ожидаемый вывод:
Пищалка запущена!
Нажмите Ctrl+C — будет звуковой сигнал
Нажмите Ctrl+\ — программа завершится с подсчетом сигналов
Ожидаю сигналов...

**Шаг 2: Генерация SIGINT**
Нажмите Ctrl+C три раза. 
Ожидаемый результат: Вы услышите три звуковых сигнала. На экране ничего не появится (сигнал обрабатывается "тихо").

**Шаг 3: Генерация SIGQUIT**
Нажмите Ctrl+\ (обычно Ctrl+Backslash).
Ожидаемый результат:
Всего прозвучало сигналов: 3
Программа завершена по SIGQUIT
(Программа корректно завершает работу и возвращает управление в терминал).
