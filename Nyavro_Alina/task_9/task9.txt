# 9: Создание двух процессов (fork/exec/wait)

## 1. Подготовка рабочего места
Переходим в директорию задания и создаем новую папку:

cd ~/MyOSTest
mkdir task_9
cd task_9

Создадим длинный текстовый файл для теста:
for i in {1..100}; do echo "Line number $i of the long file" >> long_file.txt; done

## 2. Ключевые концепции для понимания задачи

• fork(): Системный вызов, создающий точную копию текущего процесса. После вызова код программы раздваивается: родитель и ребенок выполняют один и тот же код дальше, но с разными возвращаемыми значениями fork().
• exec(): Семейство функций, заменяющих образ текущего процесса новой программой. Используется в дочернем процессе для запуска утилиты cat. Если exec успешен, код после него не выполняется.
• wait/waitpid(): Системные вызовы для синхронизации. Родительский процесс приостанавливает свое выполнение до тех пор, пока не завершится указанный дочерний процесс. Это гарантирует порядок вывода.

## 3. Шпаргалка: Управление процессами в Unix

ФУНКЦИИ (unistd.h, sys/wait.h)
• pid_t fork(void): 
  - Возвращает 0 в дочернем процессе.
  - Возвращает PID ребенка (>0) в родительском.
  - Возвращает -1 при ошибке.
• int execlp(const char *file, const char *arg, ...): 
  - Заменяет процесс новой программой, ищет её в PATH.
  - Последний аргумент обязательно должен быть NULL.
• pid_t waitpid(pid_t pid, int *status, int options): 
  - Ожидает завершения конкретного процесса с указанным PID.
  - options: обычно 0 (блокирующее ожидание).

МАКРОСЫ ДЛЯ СТАТУСА
• WIFEXITED(status): true, если процесс завершился нормально.
• WEXITSTATUS(status): возвращает код возврата (exit code) процесса.

ВАЖНО
• Без wait() родитель может завершиться раньше ребенка, оставив его "сиротой". Вывод в терминал будет перемешан.
• execlp("cat", "cat", filename, NULL): Первый "cat" — имя команды, второй — argv[0] для самой программы cat.

## 4. Основные библиотеки

#include <stdio.h>        // printf, fprintf
#include <stdlib.h>       // exit, EXIT_FAILURE
#include <unistd.h>       // fork, execlp, getpid
#include <sys/types.h>    // pid_t
#include <sys/wait.h>     // waitpid, WIFEXITED, WEXITSTATUS

## 5. Алгоритм решения

1. Проверка аргументов:
   - Убедитесь, что имя файла передано через argv[1].

2. Создание подпроцесса:
   - Вызовите pid = fork().
   - Обработайте ошибку (pid < 0).

3. Логика дочернего процесса (pid == 0):
   - Выведите сообщение о старте.
   - Вызовите execlp("cat", "cat", argv[1], NULL) для вывода содержимого файла.
   - Добавьте обработку ошибки execlp (perror + exit), так как эта строка выполнится только в случае неудачи.

4. Логика родительского процесса (pid > 0):
   - Выведите свои сообщения (например, "Parent is working...").
   - Вызовите waitpid(pid, &status, 0) для ожидания завершения ребенка.
   - Проверьте статус завершения через WIFEXITED и WEXITSTATUS.
   - Выведите финальное сообщение ("This is the last line...") строго после waitpid.

## 6. Сборка и тестирование

Создайте Makefile для сборки process_manager.c:

CC = gcc
CFLAGS = -O2
TARGET = process_manager
SRC = process_manager.c

all: $(TARGET)

$(TARGET): $(SRC)
	$(CC) $(CFLAGS) -o $(TARGET) $(SRC)

clean:
	rm -f $(TARGET)

.PHONY: all clean

Команды для запуска:
make clean
make
./process_manager long_file.txt
