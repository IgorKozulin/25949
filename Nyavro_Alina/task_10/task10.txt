10. Код завершения команды
Напишите программу, которая запускает команду, заданную в качестве первого аргумента, в виде порожденного процесса. Все остальные аргументы программы передаются этой команде. Затем программа должна дождаться завершения порожденного процесса и распечатать его код завершения.

# 10: Код завершения команды

## 1. Подготовка рабочего места
Переходим в директорию задания и создаем новую папку:

cd ~/MyOSTest
mkdir task_10
cd task_10

## 2. Ключевые концепции для понимания задачи

• Проброс аргументов: Наша программа выступает "оберткой". Она принимает список аргументов (argc, argv) и должна передать их запускаемой команде без изменений.
• execvp vs execlp: Функция execlp требует явного перечисления аргументов в коде, что неудобно при неизвестном количестве параметров. execvp принимает массив указателей (argv), что идеально подходит для проброса аргументов из main().
• Анализ статуса завершения: Просто дождаться процесса недостаточно. Нужно определить, завершился ли он штатно (через exit/return) или был прерван сигналом (например, Segmentation Fault), и вывести соответствующий код или номер сигнала.

## 3. Шпаргалка: Запуск внешних команд и анализ статуса

ФУНКЦИИ (unistd.h, sys/wait.h)
• int execvp(const char *file, char *const argv[]): 
  - Ищет исполняемый файл в директориях переменной PATH.
  - file: имя команды (например, "ls").
  - argv: массив строк-аргументов. Первый элемент — имя команды, последний — NULL.
• pid_t waitpid(pid_t pid, int *status, int options): 
  - Ожидает изменения состояния конкретного процесса.
  - status: сюда записывается информация о том, как завершился процесс.

МАКРОСЫ АНАЛИЗА СТАТУСА (sys/wait.h)
• WIFEXITED(status): Истина, если процесс завершился нормально.
• WEXITSTATUS(status): Возвращает код выхода (0-255), переданный в exit().
• WIFSIGNALED(status): Истина, если процесс был убит сигналом.
• WTERMSIG(status): Возвращает номер сигнала, убившего процесс.
• strsignal(int sig): Возвращает строковое описание сигнала (например, "Segmentation fault").

ВАЖНО
• Массив argv для execvp должен заканчиваться NULL. В нашей задаче мы передаем &argv[1], так как argv[0] — это имя нашей программы-обертки, а argv[1] — имя запускаемой команды.
• Код 127 традиционно используется в Unix для обозначения "command not found".

## 4. Основные библиотеки

#include <stdio.h>        // printf, fprintf
#include <stdlib.h>       // exit, EXIT_FAILURE
#include <unistd.h>       // fork, execvp
#include <sys/types.h>    // pid_t
#include <sys/wait.h>     // waitpid, WIFEXITED, WEXITSTATUS
#include <string.h>       // strsignal

## 5. Алгоритм решения

1. Проверка аргументов:
   - Убедитесь, что argc >= 2. Если нет, выведите сообщение об использовании (Usage) и завершите работу.

2. Создание подпроцесса:
   - Вызовите pid = fork().
   - Обработайте ошибку (pid < 0).

3. Логика дочернего процесса (pid == 0):
   - Вызовите execvp(argv[1], &argv[1]).
   - Добавьте обработку ошибки: если execvp вернул управление, значит команда не найдена.
   - Выведите ошибку через perror и завершите процесс с кодом 127 (exit(127)).

4. Логика родительского процесса (pid > 0):
   - Вызовите waitpid(pid, &status, 0) для ожидания завершения ребенка.
   - Проанализируйте статус:
     - Если WIFEXITED(status) истинно: выведите код возврата через WEXITSTATUS(status).
     - Если WIFSIGNALED(status) истинно: выведите номер сигнала через WTERMSIG(status) и его описание через strsignal().

## 6. Сборка и тестирование

Создайте Makefile для сборки run_command.c:

CC = gcc
CFLAGS = -O2
TARGET = run_command
SRC = run_command.c

all: $(TARGET)

$(TARGET): $(SRC)
	$(CC) $(CFLAGS) -o $(TARGET) $(SRC)

clean:
	rm -f $(TARGET)

.PHONY: all clean

Команды для запуска:
make clean
make

## 7. Примеры проверки

**Тест 1: Успешное выполнение**
./run_command ls -l /tmp
Ожидаемый результат:
[PARENT] Starting command: ls
... (вывод ls) ...
[PARENT] Command exited normally with code: 0

**Тест 2: Ошибка выполнения (код != 0)**
./run_command grep "nonexistent_string" /etc/passwd
Ожидаемый результат:
[PARENT] Command exited normally with code: 1

**Тест 3: Команда не найдена**
./run_command fake_command_123
Ожидаемый результат:
Execvp failed: No such file or directory
[PARENT] Command exited normally with code: 127

**Тест 4: Завершение по сигналу (Segfault)**
(Предварительно создайте программу, вызывающую segfault)
./run_command ./crash_program
Ожидаемый результат:
[PARENT] Command terminated by signal: 11 (Segmentation fault)
