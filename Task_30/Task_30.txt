30. Связь через Unix domain socket
Напишите две программы, взаимодействующих через Unix domain socket. Первый процесс (сервер) создает сокет и слушает на нем.  При присоединении клиента, сервер получает через соединение текст, состоящий из символов верхнего и нижнего регистров, переводит его в верхний регистр и выводит в свой стандартный поток вывода, аналогично задаче 25. Второй процесс (клиент) устанавливает соединение с сервером и передает ему текст.  После разрыва соединения клиентом, оба процесса завершаются.

## 2. Ключевые концепции для понимания задачи

• Unix Domain Socket: Механизм межпроцессного взаимодействия (IPC) для локальной связи между процессами на одной машине. Работает через специальный файл в файловой системе.
• Клиент-серверная архитектура: 
  - Сервер: создаёт сокет, привязывает его к файлу, слушает входящие соединения, принимает их и обрабатывает данные.
  - Клиент: создаёт сокет и подключается к файлу сервера для отправки данных.
• Потоковый сокет (SOCK_STREAM): Гарантирует надёжную доставку данных в правильном порядке (аналогично TCP, но без сетевого стека, что делает его быстрее).
• Файл сокета: После вызова `bind()` в файловой системе появляется файл. Он не содержит самих данных, а служит "точкой входа" (адресом) для подключений.

## 3. Шпаргалка: Unix Domain Sockets

СТРУКТУРЫ И ФУНКЦИИ (sys/socket.h, sys/un.h)
• struct sockaddr_un: Структура адреса для Unix domain socket.
  - sun_family: AF_UNIX (или AF_LOCAL).
  - sun_path: Путь к файлу сокета в файловой системе (например, "./socket").

• int socket(int domain, int type, int protocol): 
  Создаёт сокет. domain = AF_UNIX, type = SOCK_STREAM, protocol = 0.

• int bind(int sockfd, const struct sockaddr *addr, socklen_t addrlen): 
  Привязывает сокет к адресу (файлу в файловой системе).

• int listen(int sockfd, int backlog): 
  Начинает слушать входящие соединения. backlog — максимальное количество ожидающих соединений в очереди (например, 5).

• int accept(int sockfd, struct sockaddr *addr, socklen_t *addrlen): 
  Принимает входящее соединение. Блокируется до подключения клиента. Возвращает новый файловый дескриптор для общения с этим конкретным клиентом.

• int connect(int sockfd, const struct sockaddr *addr, socklen_t addrlen): 
  Подключается к серверу (используется клиентом).

• ssize_t read(int fd, void *buf, size_t count) / write(...): 
  Чтение и запись данных через сокет работают точно так же, как с обычным файлом.

• int unlink(const char *pathname): 
  Удаляет файл сокета из файловой системы.

ВАЖНЫЕ НЮАНСЫ
• Всегда вызывайте unlink(SOCKET_PATH) перед bind() на сервере. Иначе при повторном запуске bind() вернет ошибку "Address already in use".
• После завершения работы сервера файл сокета необходимо удалить через unlink(), чтобы не засорять файловую систему.
• Unix domain sockets работают только в пределах одной машины, но они значительно быстрее TCP/IP, так как данные не проходят через сетевой стек.
• Клиент может получить SIGPIPE, если сервер закроет соединение раньше.
Игнорируйте SIGPIPE через signal(SIGPIPE, SIG_IGN) и проверяйте errno == EPIPE
  после write — это переносимо и не убивает процесс.
• write может записать меньше запрошенного. Для надёжности используйте
обёртку write_all, которая в цикле дописывает остаток.
• После read проверяйте errno == EINTR (прерывание сигналом) и повторяйте
read, а не считайте это ошибкой.

## 5. Алгоритм решения

**Сервер (server.c):**
1. Очистка: Вызовите `unlink(SOCKET_PATH)` для удаления старого файла сокета, если он существует.
2. Создание: Вызовите `socket(AF_UNIX, SOCK_STREAM, 0)`.
3. Настройка адреса: Обнулите структуру `sockaddr_un` через `memset`, установите `sun_family = AF_UNIX` и скопируйте путь в `sun_path`.
4. Привязка: Вызовите `bind()` с созданным сокетом и структурой адреса.
5. Прослушивание: Вызовите `listen()` с разумным размером очереди (например, 5).
6. Принятие соединения: Вызовите `accept()`. Он заблокирует выполнение до подключения клиента и вернет новый дескриптор `client_fd`.
7. Обработка данных: В цикле `while` читайте данные из `client_fd` через `read`. Для каждого прочитанного байта применяйте `toupper((unsigned char)buffer[i])` и выводите результат через `write(STDOUT_FILENO, ...)`.
8. Завершение: При получении EOF (read вернет 0) закройте `client_fd` и `server_fd`, затем вызовите `unlink(SOCKET_PATH)`.

**Клиент (client.c):**
1. Создание: Вызовите `socket(AF_UNIX, SOCK_STREAM, 0)`.
2. Настройка адреса: Заполните `sockaddr_un` путем к сокету сервера (`SOCKET_PATH`).
3. Подключение: Вызовите `connect()` с дескриптором сокета и структурой адреса.
4. Отправка данных: В цикле отправляйте подготовленные сообщения через `write(sock_fd, message, strlen(message))`.
5. Завершение: Закройте сокет через `close()`, что разорвет соединение и отправит серверу сигнал EOF.

## 6. Сборка и тестирование

Создайте Makefile для сборки server.c и client.c:

CC = gcc
# POSIX-макрос и библиотеки сокетов, специфичные для Solaris/Illumos
CFLAGS = -O2 -Wall -Wextra -D_POSIX_C_SOURCE=200112L
LDFLAGS = -lsocket -lnsl
TARGETS = server client

all: $(TARGETS)

server: server.c
	$(CC) $(CFLAGS) -o server server.c $(LDFLAGS)

client: client.c
	$(CC) $(CFLAGS) -o client client.c $(LDFLAGS)

clean:
	rm -f $(TARGETS) *.o socket

.PHONY: all clean

Команды для запуска:
make clean
make
