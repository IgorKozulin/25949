# 32: Асинхронный ввод-вывод (POSIX AIO)

## 1. Подготовка рабочего места
Переходим в директорию задания и создаем новую папку:

cd ~/MyOSTest
mkdir task_32
cd task_32

## 2. Ключевые концепции для понимания задачи

• Асинхронный I/O (AIO): Вместо блокирующего ожидания или ручного опроса (select/poll), мы ставим заявку ядру: "прочитай из этого сокета в этот буфер и уведоми меня, когда закончишь". Пока ядро читает, процесс свободен.
• Уведомление через опрос (SIGEV_NONE): На Solaris/Illumos уведомление через сигналы (SIGEV_SIGNAL) для сокетов работает нестабильно. Надежнее использовать опрос состояния заявки через `aio_error()` в главном цикле с небольшой паузой (`usleep`), что не нагружает CPU.
• Чтение: важный нюанс для Solaris. `aio_read()` с сокетом и большим буфером может "зависнуть" в ожидании полного заполнения буфера. Установка `aio_nbytes = 1` гарантирует, что заявка завершится сразу при приходе любого символа.
• Блокирующие сокеты для клиентов: `accept()` наследует флаг `O_NONBLOCK` от слушающего сокета. POSIX AIO на Solaris корректно работает только с блокирующими сокетами. Поэтому после `accept()` необходимо явно сбросить флаг `O_NONBLOCK` у клиентского дескриптора.
• Обработка EAGAIN: Возврат `EAGAIN` из `aio_error()` на Solaris означает нормальное состояние "заявка есть, но результат ещё не готов". Это не ошибка, и закрывать клиента в этом случае нельзя.

## 3. Шпаргалка: POSIX AIO (Asynchronous I/O)

СТРУКТУРЫ (aio.h)
• struct aiocb (Asynchronous I/O Control Block): "Заявка" на операцию.
  - aio_fildes: файловый дескриптор (сокет клиента).
  - aio_buf: указатель на буфер для данных.
  - aio_nbytes: размер операции в байтах (для Solaris с сокетами = 1).
  - aio_offset: смещение (для сокетов не используется, ставим 0).
  - aio_sigevent: структура, определяющая способ уведомления о завершении.

• struct sigevent (настройка уведомления):
  - sigev_notify: способ уведомления (SIGEV_NONE — опрос, SIGEV_SIGNAL — сигнал, SIGEV_THREAD — вызов функции в новом потоке).
  - sigev_signo: номер сигнала (если выбран SIGEV_SIGNAL).
  - sigev_value.sival_ptr: указатель на пользовательские данные, передаваемый в обработчик.
  - sigev_notify_function: указатель на функцию, которая будет вызвана (если выбран SIGEV_THREAD).

ФУНКЦИИ (aio.h)
• int aio_read(struct aiocb *cb): Ставит операцию чтения в очередь и сразу возвращается.
• int aio_error(const struct aiocb *cb): Проверяет состояние заявки.
  - EINPROGRESS: операция ещё выполняется.
  - EAGAIN: заявка не готова к получению результата (нормальное состояние на Solaris).
  - 0: операция успешно завершена.
  - другое: код ошибки.
• ssize_t aio_return(struct aiocb *cb): Возвращает результат завершенной операции (аналог return от read). Вызывать ровно один раз для каждой завершенной заявки! (>0: прочитано байт, 0: EOF/клиент отключился, -1: ошибка).
• int aio_cancel(int fd, struct aiocb *cb): Отменяет незавершенные операции (используется при корректном завершении сервера).

ВАЖНЫЕ НЮАНСЫ
• Каждая заявка `aiocb` одноразовая. После успешного чтения необходимо заново вызывать `aio_read()` для этого же клиента.
• На Solaris/Illumos функции `aio_*` находятся в библиотеке `librt`, поэтому при сборке обязательно указывать флаг `-lrt`.
• Слушающий сокет можно сделать неблокирующим (`O_NONBLOCK`) для удобного `accept`, но клиентские сокеты должны быть блокирующими.

## 5. Алгоритм решения (Детальная спецификация)

**Сервер (server.c):**
1. Структура клиента: Определите `struct client`, содержащую: `int fd`, `struct aiocb cb`, `char byte` (буфер ровно на 1 байт), `int active`, `int id`. Создайте массив таких структур (например, на 100 элементов) и инициализируйте все `fd` как `-1`.
2. Сигналы: Зарегистрируйте обработчик для `SIGINT`/`SIGTERM`, меняющий глобальный флаг `keep_running` на 0.
3. Сокет сервера: `socket`, `bind` (предварительно сделав `unlink` файла сокета), `listen`.
4. Неблокирующий accept: Установите `O_NONBLOCK` только для слушающего сокета через `fcntl`.
5. Главный цикл (`while keep_running`):
   - **Прием подключений:** В цикле вызывайте `accept`. Если успешно, найдите свободный слот в массиве клиентов (где `fd == -1`).
   - **Критический шаг:** Сбросьте флаг `O_NONBLOCK` у нового клиентского сокета: `fcntl(new_fd, F_SETFL, cflags & ~O_NONBLOCK)`. Иначе AIO на Solaris не сработает.
   - **Постановка заявки (`arm_read`):** 
     - Обнулите `aiocb` через `memset`.
     - Установите: `aio_fildes = fd`, `aio_buf = &client.byte`, `aio_nbytes = 1`, `aio_offset = 0`.
     - Установите `aio_sigevent.sigev_notify = SIGEV_NONE`.
     - Вызовите `aio_read`. Если вернул `-1`, проверьте `errno`: если это `EAGAIN` или `EINPROGRESS`, это НЕ ошибка, заявка поставлена. Иначе — реальная ошибка.
   - **Опрос клиентов:** Пройдите по всем активным клиентам и вызовите `aio_error(&client.cb)`.
     - Если `EINPROGRESS` или `EAGAIN`: пропустите (заявка в процессе).
     - Если `err != 0 && err != ECANCELED`: реальная ошибка. Закройте сокет, освободите слот (`fd = -1`, `active = 0`).
     - Если `0` (успех): вызовите `aio_return`. 
       - Если `> 0`: преобразуйте `client.byte` в верхний регистр (`toupper`), выведите через `write(STDOUT_FILENO, &client.byte, 1)`, и вызовите `arm_read` для этого же клиента снова.
       - Если `== 0` (EOF): клиент отключился. Закройте сокет, освободите слот.
   - **Пауза:** Вызовите `usleep(10000)` (10 мс), чтобы не нагружать CPU в цикле опроса.
6. Завершение: Пройдите по всем клиентам, вызовите `aio_cancel`, закройте сокеты, закройте слушающий сокет и удалите файл через `unlink`.

**Клиент (client.c):**
1. Игнорирование SIGPIPE: В начале `main` вызовите `signal(SIGPIPE, SIG_IGN)`, чтобы при закрытии сервера клиент не падал.
2. Подключение: `socket`, настройка адреса, `connect`.
3. Отправка данных: В цикле отправляйте сообщения. Для соответствия ожидаемому выводу сервера, формируйте строку так: `snprintf(buf, sizeof(buf), "[%s] %s", name, messages[i])`, где `name` берется из `argv[1]` (или "client" по умолчанию).
4. Сообщения: Отправьте ровно эти три строки: `"hello from client\n"`, `"this is a test message\n"`, `"asynchronous io is awesome\n"`.
5. Задержка: Добавьте `usleep(500000)` (0.5 сек) между отправками сообщений, чтобы наглядно продемонстрировать параллельную обработку на сервере.
6. Завершение: `close(sock_fd)`, что отправит серверу EOF.

## 6. Сборка и тестирование

Создайте Makefile для сборки server.c и client.c:

CC = gcc
# Макрос POSIX + библиотеки сокетов и realtime (aio_*) для Solaris/Illumos
CFLAGS = -O2 -D_POSIX_C_SOURCE=200112L
LDFLAGS = -lsocket -lnsl -lrt
TARGETS = server client

all: $(TARGETS)

server: server.c
	$(CC) $(CFLAGS) -o server server.c $(LDFLAGS)

client: client.c
	$(CC) $(CFLAGS) -o client client.c $(LDFLAGS)

clean:
	rm -f $(TARGETS) *.o socket

.PHONY: all clean

ВАЖНО: Перед командами `$(CC)` и `rm` в Makefile должен стоять символ ТАБУЛЯЦИИ, а не пробелы! Иначе вы получите ошибку `missing separator`.

Команды для запуска:
make clean
make

## 7. Пример проверки

**Важно:** Для проверки параллельности откройте три окна терминала.

**Терминал 1 (Сервер):**
./server
Ожидаемый вывод:
[СЕРВЕР] AIO-сервер запущен на ./socket
[СЕРВЕР] Ctrl+C для остановки.

**Терминал 2 (Клиент А):**
./client Alice

**Терминал 3 (Клиент Б):**
./client Bob

**Терминал 1 (Сервер) — ожидаемый вывод:**
[СЕРВЕР] Клиент 1 подключён (slot=0 fd=4). Всего: 1
[СЕРВЕР] Клиент 2 подключён (slot=1 fd=5). Всего: 2
[ALICE] HELLO FROM CLIENT
[BOB] HELLO FROM CLIENT
[ALICE] THIS IS A TEST MESSAGE
[BOB] THIS IS A TEST MESSAGE
[ALICE] ASYNCHRONOUS IO IS AWESOME
[BOB] ASYNCHRONOUS IO IS AWESOME
[СЕРВЕР] Клиент 1 отключился (EOF). Осталось: 1
[СЕРВЕР] Клиент 2 отключился (EOF). Осталось: 0

*Примечание:* Вывод клиентов перемешан, что разрешено условием. 
Сервер не ждет завершения одного клиента, чтобы обслужить другого.
